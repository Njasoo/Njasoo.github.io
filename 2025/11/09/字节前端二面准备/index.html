event loop

js 是单线程的，但是它是并行的，所以它就是通过调度器不断地遍历队列里面的任务来执行逻辑

如果要回答面试官的问题的话，就这么说，event loop 是 js 执行异步代码的一种调度方案，目的是为了保证异步代码能够按顺序执行，然后它的执行顺序就是同步任务，微任务，宏任务这样，其实还有更细节的回答，但是那些我不懂，没用过，就不强答了

TCP 和 IP 分别是什么层的协议

首先复习一下，网络的分层结构，当我们在说理论上的结构的时候，我们默认的是 OSI 七层结构，自顶向下分别是，应用层，表示层，会话层，传输层，网络层，数据链路层，物理层，但是这七层我是不会背的，实际开发当中，用的是四层的结构，五层的结构是为了教学才提出的，四层的结构就是应用层，传输层，网络层，网络接口层

那么 TCP 其实是传输层的协议，因为它主要是实现了可靠传输的功能，所以和传输是比较有关系的

然后 IP 协议是网络层的协议，负责的东西是寻址和路由，但是这两个说实话，都不是很适合去记，因为实际上我也没用过这方面的知识

AI 帮到了我什么

AI 在前端这一方面主要帮到我的地方是 UI 生成的部分，我会让 AI 先按照我的要求写一个初版的组件给我，然后我在那基础上再进行微调，AI 的另外一个作用就是帮我进行 debug，很多时候我在写前端页面的时候，可能会出现页面不显示的情况，发生了一些报错，但是因为前端的代码比较多，我肉眼可能看不出来语法错误在哪，一行一行去看的话，太浪费时间，如果没有办法在短时间之内找到错误的话，我会选择使用 AI 来帮助自己进行 debug，在大部分的情况下，AI 都能很快地找到，大大节省我花在上面的时间

其实 UI 这方面最大的问题不是它难不难写，最大的问题是我写不出好看的风格出来，因为我可能没有接受一些美术方面的专业培养，所以在没有设计稿的情况下，让我自己去写 UI 的话，可能不是太美观，所以我会让 AI 来帮我先生成一个初始的组件样式，然后我再进行微调

剩下的就是比较进阶的了，我碰都没碰过

ref 和 reactive 的具体区别是什么

上次我说了就是多了一个.value 的调用，然后 ref 尽量用在基本类型，reactive 尽量用在数组和对象上面，好像也对吧，但是上次面试官问说直接用 ref 替代 reactive 会不会出现什么问题

听说 ref 可以直接给对象重新赋值，就是 obj.value = { …: … }这样，这样是可以的，但是如果用 reactive 的话，就可能会变成普通的数据，而不是响应式的，我感觉非常的合理

那么为什么通常建议 ref 用在基础类型，而 reactive 用在数组和对象上面呢，其实最根本的原因就是 reactive 不能用在基础类型上面，它只能接受数组和对象，所以我想大家其实是比较希望什么数据类型都用 reactive，可能是因为代码写起来比较简洁

所以应该这么说，如果需要经常替换对象整体的话，就会用 ref，但是如果是频繁地修改内部字段的话，就应该用 reactive
