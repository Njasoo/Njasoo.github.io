express项目结构

路由操作(接口)

在routes文件夹下创建对应表的route(这里是接口的意思), 命名格式统一为<表名>_route.js吧

为了避免回调地狱, 我们要用同步的方法来编写接口

restful api 规范

类似这样

目的 方法 URI
取得所有使用者資料 GET /users
新增使用者 POST /users
取得某位使用者資料 GET /users/{id}
更改某位使用者資料 PUT/PATCH /users/{id}
删除某位使用者 DELETE /users/{id}

数据库

安装依赖

sequelize库是ORM方式操作数据库的, 就是利用对象来操作, 而不是主要直接运行sql语句

mysql2是sequelize操作MySQL的底层驱动

相关配置

数据库的相关配置我们会定义在/config文件夹里面

表定义

定义在/models里面, 命名格式为<表名>_model.js

modelName是表在数据库当中实际的名字, 而tableName是代码引用的名字

不给TableName的话, 那么代码引用的就是modelName

动态加载路由 也许是为了避免二级路由嵌套太多层吧, 可以使用动态加载路由的方法来避免嵌套, 当登录后再加载路由, 可以通过vuex或者pinia维护一个全局变量, 配合路由守卫, 判断是否已经登录过, 如果登陆过就就直接放行, 否则就加载新的路由, 然后再放行, 这里的next就要指定路径了 pinia的持久化存储 pinia在页面刷新的时候会重新初始化store的属性, 导致全局变量内容丢失, 可以通过安装插件来改变pinia的存储方式, 使得数据的存储变成持久化的, 也就是说刷新之后仍能保持不变 1npm install pinia-plugin-persistedstate 跨域请求 前端访问后端接口的时候, 如果没有配置好跨域请求的部分会被block, 最标准的解决方案是在后端设置响应头, 指定哪些域名是可以访问到这些借口的 或者前端在开发环境下使用代理服务器
