# js 排序函数，自定义排序规则

我直接给一个复合一点的例子吧，就是一个对象数组的排序

```js
const a = [
  { id: 0, name: "0" },
  { id: 1, name: "1" },
  { id: 2, name: "2" },
  { id: 3, name: "3" },
  { id: 4, name: "4" },
];

a.sort((i, j) => j.id - i.id);
console.log(a);
```

那么这个排序函数很简单，对 sort 函数传入一个匿名函数，返回结果<=0 的排在则相对相对顺序不变，>0 相对顺序改变，就是这么简单，所以上面的程序就是把这个对象数组按 id 从大到小排序

浅浅地讲一下，怎么比较字典序，其实大于小于号也是可以的，但是在比较汉字的时候可能会有点问题，比较不可控，我也不太清楚不可控是什么意思，但是总之用 localeCompare 是比较稳的，给个代码

```js
const arr = ["张三", "李四", "王五"];
arr.sort((i, j) => i.localeCompare(j));
console.log(arr);
```

解释一下这个 localeCompare 函数，就是 i < j 的时候，返回负数，>的时候返回正数，相等返回 0，就是这么简单

# Promise 对象学习

## 同步任务和微任务

首先 Promise 对象是用来处理异步操作的，然后操作完之后，会返回一个确定的状态，一开始状态是 pending，然后成功与否就是 fullfilled 和 rejected，一旦确定之后是不会改变的

promise 对象都有一个.then 函数可以调用，这个 then 里面的逻辑称为一个微服务，微服务会被添加到队列里面等待执行，同步代码会先被执行，同步代码是什么，同步代码就是那些非异步操作的代码，我下面给个例子

```js
console.log(1);
Promise.resolve().then(() => console.log(2));
console.log(3);
```

首先这里第一行和第三行的代码都是同步代码，然后 then 里面的逻辑是异步的，是一个微服务，要被添加到队列里面，但是这里有个很坑的点，我老是错，就是这个 then 里面要传一个函数的引用，这个程序的执行结果是 1 3 2，但是如果程序长下面这个样子，结果将完全不同

```js
console.log(1);
Promise.resolve().then(console.log(2));
console.log(3);
```

这样的话，执行结果就是 1 2 3 了，其实这段代码等价于下面这样

```js
console.log(1);
console.log(2);
Promise.resolve().then(undefined);
console.log(3);
```

因为 console.log()是没有返回值的，只是一个 undefined，这样的话，这个代码的逻辑就很清晰很合理了

那么回到正题，同类任务之间的执行顺序就是代码顺序，然后微服务的执行要在同步任务执行完毕之后才能执行

## then 的链式传递

```js
Promise.resolve(1)
  .then((x) => {
    return x + 1;
  })
  .then((x) => {
    return x + 1;
  })
  .then((x) => {
    console.log(x);
  });
```

这段代码的结果是 3，就是这个函数的返回值就是传递到下一个 then 的参数那里，就记得 then 是有传递性的就行了

```js
Promise.resolve()
  .then(() => {
    console.log("X");
    return Promise.resolve("Y"); // 等它 resolve
  })
  .then((v) => console.log(v));
```

这道题的结果是 X Y，正如我所想，但是原理好像和我想的不一样，这里说的是 then 会等待 Promise 返回结果，而这个 Promise 它返回的结果就是 Y，我以为是立即返回结果呢，不过总体上答案一样的就是了，然后这个 v 也是从上一个 then 的返回结果继承过来的，所以用到了链式法则

## then 和定时器的执行顺序

```js
console.log("A");

setTimeout(() => console.log("B"), 0);

Promise.resolve().then(() => console.log("C"));

console.log("D");
```

这个程序的执行结果是 A D B C，简单地说明下，setTimeout 这件事情是一个宏任务，三种任务的执行顺序如下: 同步任务 > 微任务 > 宏任务

顺便解释一下宏任务是什么，宏任务就是 setTimeout，Dom 时间回调比如 click、keydown 这些事件，IO 操作之类的，其他的我看不懂了，就不过多解释，我觉得能答到这份上就行了

## await 阻塞的范围

```js
async function test() {
  console.log(1);
  await Promise.resolve();
  console.log(2);
}
test();
console.log(3);
```

这道题的运行结果是，1 3 2，首先 1 是很明显的，不用解释，但是这里我以为 await 只会让 Promise.resolve()这段代码放到微服务队列里面，然后 console.log(2)这段代码同样的执行，最后执行 console.log(3)，但是我在理解答案之后也感觉这个答案非常的离谱，因为 await 这句代码的作用就是让后续的代码等待它的返回结果，先不要执行，所以其实 await 的作用就是让函数里面的后续代码全部放进微服务队列里面，然后这里 console.log(3)是一个同步代码，console.log(2)也被放到了微服务队列里面，所以结果应该是 1 3 2 猜对，这里详细地说一下，await 函数只能在 async 函数里面使用，其实他具体的作用应该就是把整个函数放到了微服务队列里面（当然还是记录了一下执行位置）

# 闭包

虽然我大概知道这是个什么东西了，但是还是着重地复习一下这一部分，因为这好像是一个高频的面试内容，然后好像其实也是蛮有用的，闭包就是一个外部函数包住一个内部函数，然后内部函数，引用了外部函数作用的变量，那么这个内部函数以及这个外部变量形成了一个特别的作用域，这就是一个闭包，下面我给一段代码作为例子

```js
function makeCounter() {
  let count = 0;
  return function () {
    return ++count;
  };
}

let counter = makeCounter();
console.log(counter());
console.log(counter());
```

这段代码的执行结果是 1 2，很神奇吧，这个内部函数居然会记得 count 这个变量，听说原理就是，原本在函数里面的局部变量正常都会放在栈区，但是闭包的话，外部变量会放在堆区，相当于一个全局变量吧，所以这个变量能一直被记住

# 最长不重复子串

```cpp
class Solution {
public:
    int lengthOfLongestSubstring(string s) {
        int i = 0;
        int n = s.size();
        int j = 0;
        vector<int> cnt(114514);
        int mxlen = 0;
        while (i < n) {
            j = max(j, i);
            while (j < n && cnt[s[j]] == 0) {
                cnt[s[j]]++;
                j++;
            }
            // [i, j - 1]
            int len = j - i;
            if (len > mxlen) {
                mxlen = len;
            }
            cnt[s[i]]--;
            i++;
        }
        return mxlen;
    }
};
```

思路很简单啦，就是双指针，注意一下右端点的含义就行

# TCP 和 IP 分别是什么层的协议

# ref 和 reactive 的具体区别是什么

上次我说了就是多了一个.value 的调用，然后 ref 尽量用在基本类型，reactive 尽量用在数组和对象上面，好像也对吧，但是上次面试官问说直接用 ref 替代 reactive 会不会出现什么问题

听说 ref 可以直接给对象重新赋值，就是 obj.value = { ...: ... }这样，这样是可以的，但是如果用 reactive 的话，就可能会变成普通的数据，而不是响应式的，我感觉非常的合理

那么为什么通常建议 ref 用在基础类型，而 reactive 用在数组和对象上面呢，其实最根本的原因就是 reactive 不能用在基础类型上面，它只能接受数组和对象，所以我想大家其实是比较希望什么数据类型都用 reactive，可能是因为代码写起来比较简洁

所以应该这么说，如果需要经常替换对象整体的话，就会用 ref，但是如果是频繁地修改内部字段的话，就应该用 reactive
